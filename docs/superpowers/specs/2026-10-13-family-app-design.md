# Семейный помощник: каркас и первый срез

Черновик от 13.10.2026, ждёт проверки владельцем. Продукт описан в `PRODUCT.md`, внешний вид — в `DESIGN.md` и макете `mockups/index.html` (версия «Ягода»), риски доступа из РФ — в `docs/research/2026-10-13-tech-risks.md`.

## Первый срез

Что войдёт:

- **Вход и семья.** Вход через Google или по почте с паролем. Приглашение в семью ссылкой. Роли «родитель» и «ребёнок» назначает владелец. У Димы профиль без входа.
- **Настройки.** Профиль, тема «День / Ночь / Как в телефоне», семья и роли, «не едим», время еды, уведомления, выход.
- **Меню.**
  - **Выбор недели.** Шаблоны недель показаны с примерной ценой и с меню по дням.
    - Родитель ставит шаблон на текущую неделю.
    - Любой член семьи предлагает шаблон на следующую неделю, семья голосует, родитель утверждает.
  - **Замена.** Любой приём пищи меняется на блюдо из любого дня любого шаблона, на блюдо из своей недели или на любой рецепт базы. Целый день меняется на любой день любого шаблона. После замены список покупок пересчитывается.
  - **Свои недели.** Получившуюся неделю можно сохранить как свой шаблон. Редактор своих рецептов — во втором срезе, до него новые рецепты и недели добавляются в начальную базу.
  - **«Что покушать».** Подборки, поиск по блюду и продукту. Блюдо можно предложить члену семьи: кому, когда, поверх меню или вместо блюда.
- **Покупки.** Утверждённая неделя сама собирает список с количествами и примерной стоимостью. Кроме того:
  - ручные позиции с пометкой «срочно»;
  - отделы магазина;
  - «Иду в магазин» с уведомлением семье;
  - отметки, видные всем;
  - копирование списка текстом.
- **Главная** в объёме этих модулей:
  - ряд «Семья»;
  - главное сейчас: предложенное мне блюдо, срочная покупка или ужин (просьбы появятся с Доской);
  - «Сегодня едим»;
  - «Предложили на сегодня».

Доска и Деньги — второй срез. До него во вкладках только Главная, Меню и Покупки.

Срез готов, когда на телефонах семьи проходят шесть проверок:

1. Неделю на следующую неделю предлагают, голосуют за неё и утверждают в приложении. Чат и бумага для этого не нужны.
2. Любой приём пищи и любой день меняются на блюдо или день из другой недели, а список покупок после этого сходится с меню.
3. После утверждения в списке покупок есть каждый продукт из блюд недели. Количество — сумма по всем дням, с учётом порций семьи.
4. Двое отмечают покупки в магазине и видят отметки друг друга без обновления страницы.
5. Без интернета список открывается и отмечается. Отметки уходят на сервер, когда сеть появляется.
6. Приложение открывается и входит у каждого члена семьи по мобильному интернету и по Wi-Fi.

## Шаг 0: проверка доступа

До кода приложения выкладываем страницу-проверку на Vercel и на Yandex Object Storage. Каждый член семьи открывает её на своём телефоне дважды: на мобильном интернете и на Wi-Fi.

Страница проверяет четыре вещи:

- ответ Supabase API больше 16 КБ приходит целиком (ограничение провайдеров на Cloudflare);
- открывается вход Google;
- открывается вход по почте;
- работает Realtime.

Итог — таблица «телефон × сеть × проверка».

- **Всё прошло:** Supabase Cloud, хостинг Vercel.
- **Не открывается Vercel:** та же сборка переезжает на Yandex Object Storage, код не меняется.
- **Не проходит Supabase:** выбираем между nginx-прокси на российском VPS и своим бэкендом. Варианты и цены — в ресёрче рисков.

## Каркас

| Часть | Решение |
|---|---|
| Клиент | React + Vite + TypeScript, PWA через vite-plugin-pwa. Шрифт Onest раздаём со своего хостинга. |
| Данные на телефоне | IndexedDB через Dexie. Экраны читают только локальную базу. |
| Запись | Сначала в локальную базу и в очередь изменений, потом очередь уходит на сервер. |
| Синхронизация | Своя, небольшая. Данных у семьи сотни строк, поэтому достаточно двух механизмов: при запуске и по событию Realtime подтягиваем строки с `updated_at` новее последней синхронизации; очередь отправляем через upsert. Удаление мягкое (`deleted_at`). При конфликте побеждает последняя запись. Исключение — отметка «куплено»: это установка значения, а не переключение, поэтому двойная отметка ничего не ломает. |
| Сервер | Supabase: Postgres, Auth, Realtime, Edge Functions, pg_cron. |
| Доступ | Row Level Security. Каждая строка принадлежит семье (`household_id`). Деньги и пометки «берём в подарок» видит только роль `parent`. |
| Вход | Supabase Auth: Google и почта с паролем. Приглашение — ссылка с одноразовым кодом и ролью. |
| Пуши | Web Push (VAPID), отправка из Edge Function. Шифрование на Web Crypto: библиотека `web-push` в edge-среде не работает. В первом срезе пушей три: предложена неделя, предложено блюдо, кто-то идёт в магазин. Важное дублируется внутри приложения. |
| Хостинг | Vercel. Запасной — Yandex Object Storage, см. шаг 0. |

Бесплатный проект Supabase засыпает после 7 дней без активности. Семья заходит каждый день, поэтому на старте это не мешает. Если проект всё же уснёт, разбудить его можно кнопкой в панели Supabase.

## Модель данных первого среза

Начальная база (рецепты, продукты, шаблоны недель) лежит в тех же таблицах, что и данные семьи, с `household_id = null`. Семья видит её и добавляет свои записи.

| Таблица | Что хранит |
|---|---|
| `households` | семья |
| `members` | член семьи: имя, цвет, роль, владелец ли, есть ли вход (`user_id`), доля порции (1 или 0,5) |
| `invites` | приглашения: код, роль, срок, кто использовал |
| `member_settings` | время еды, уведомления, тема (тема ещё и в локальном хранилище телефона) |
| `ingredients` | продукт: единица, отдел магазина, группа для баланса, вес штуки, «всегда есть дома», цена за единицу и её источник |
| `recipes` | блюдо: категория, приёмы пищи, время, порции, сколько дней хранится, главный белок, теги, сезон, подборки «Что покушать», пометка для Димы, шаги, ссылка на источник |
| `recipe_ingredients` | продукт в блюде: количество, пометка, «по вкусу» |
| `recipe_sides` | подходящие гарниры |
| `week_templates`, `template_slots` | шаблон недели: день, приём пищи, блюдо, гарнир. У супа отмечен первый день кастрюли. |
| `weeks`, `week_slots` | конкретная неделя семьи. Статус: черновик → голосование → утверждена. |
| `votes` | голос за неделю: «за» или «есть правки» с комментарием |
| `dish_offers` | предложение блюда: от кого, кому (или всем), блюдо, дата, приём пищи, «поверх» или «вместо», статус, кто взялся |
| `not_eat` | продукты и блюда, которые семья не ест |
| `shopping_items` | позиция списка: продукт или свободный текст, количество, отдел, срочно, откуда (меню, вручную, предложение блюда), кто добавил, куплено, кто и когда купил, цена примерная и реальная |
| `push_subscriptions` | подписки на пуши по устройствам |

Как собирается список покупок:

1. Для каждого слота утверждённой недели берём продукты блюда и гарнира.
2. Количество умножаем на (сумма долей порций семьи / порций в рецепте). Сейчас доли дают 1 + 1 + 1 + 0,5 = 3,5.
3. Суп считаем один раз на кастрюлю, а не на каждый день.
4. Продукты «всегда есть дома» в список не идут.
5. Остальное суммируем по продукту и раскладываем по отделам.

Взятое предложение блюда добавляет свои продукты так же. Если неделю меняют после утверждения, пересчитываются только позиции из меню, которые ещё не куплены.

Цена продукта берётся из `content/prices.json`. Порядок источников:

1. Цена в Магните, Краснодар (Магнит Экстра). На magnit.ru ищем продукт и берём медиану цены за кг, л или штуку по подходящим товарам.
2. Нет в Магните — средняя цена Росстата по Краснодару за месяц.
3. Нет и там — средняя по РФ.

Пятёрочка и Озон Фреш при сборе 13.10.2026 закрылись проверкой от ботов, её мы не проходим. Цены устаревают, поэтому сбор повторяется раз в месяц: скрипт `content/tools/build_prices.py`.

У продукта без цены сумма списка показывается «≈ N ₽ без M продуктов». После покупки можно вписать реальную цену, дальше считается по ней.

## Начальная база рецептов

- **Рецепты.** Собраны 13.10.2026 в `content/recipes/*.json` по формату `content/SCHEMA.md`: около 200 блюд с источниками. Разделы: завтраки и полдники, супы и салаты, птица и рыба с гарнирами, мясо и блюда без мяса, «Что покушать».
- **Продукты.** Словарь — `content/ingredients.json`.
- **Шаблоны недель.** Собираются из этих рецептов и проверяются скриптом по правилам баланса из `docs/research/2026-10-13-content-sources.md`:
  - рыба не реже 2 раз в неделю;
  - птицы примерно в 1,4 раза больше, чем красного мяса;
  - овощей и фруктов от 400 г на человека в день без картофеля;
  - яйца и творог — по недельной норме Минздрава;
  - для Димы бобовые и сладкое не чаще 2–3 раз в неделю.
- **Проверка владельцем.** Владелец просматривает базу до загрузки. Что он уберёт или поправит, в базу не попадёт.

## Проверки качества

- **Модульные тесты:**
  - сборка списка покупок, пересчёт порций, суп один раз на кастрюлю;
  - проверка баланса недели;
  - очередь синхронизации при обрыве сети.
- **База данных.** Политики RLS проверяются SQL-тестами: ребёнок не читает деньги и подарки, чужая семья не читает ничего.
- **Сквозные сценарии (Playwright):**
  - утвердили неделю → появился список;
  - отметили покупку без сети → после появления сети отметка на сервере;
  - предложили блюдо → у получателя оно на Главной.
- **На телефонах семьи.** Проверки шага 0 и шесть проверок готовности среза.

## Не входит в первый срез

- Доска и Деньги, напоминания о платежах.
- Обёртка Capacitor.
- Банк, живые цены магазинов, корзина доставки: публичного API у сетей нет, остаётся копирование списка.
- Фотографии блюд.
